How it works — without Forge (default)

Three services on the edge. relay-edge stamps context and publishes; Relay runs the closed loop; pubsub is both the Pub/Sub wire and the Action Gateway.

① relay-edge :18086 Season / site / zone / device · recipients · recommended_action · verification probe
↓ POST …/topics/{type}:publish (JWT)
② relay-pubsub :8081 relay-events → maps topic to event type → POST Relay /v1/events
↓ Accept · policy match
③ Relay :8443 Notify (FCM/SMS) → operator Ack → Approve in Relay UI (native — no Forge)
↓ Act — POST /v1/actions
④ pubsub Action Gateway Returns rpg_* provider id · command reaches farm/sim controller target
↓ Verify (optional)
⑤ Relay Verify job GET probe URL stamped by relay-edge · expect JSON path match → verified

Forge Zeus · awaiting_decision · Decision Records — not used unless Forge is deployed and policy sets decision_backend: forge.

What each gate proves

  • Farm catalog — 10 Pub/Sub types through gateway; 5 critical acts reach POST /v1/actions (rpg_* provider).
  • Simulators — firewater, remote-edge, and fleet scenarios stamp context and publish new Relay events.
  • Forge path — policy decision_backend: forge; operator ack → Forge freeze Approved/Rejected → Relay act or fail.
